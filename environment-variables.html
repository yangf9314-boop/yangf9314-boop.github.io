环境变量与模型交流方式总结

2026 年 11 月 27 日 · 已脱敏

说明：文中的接口地址、模型名称和账号相关信息已用示例替换，保留的是原理和操作思路。

一、今天完成了什么

  • 将 API Key 和接口地址永久保存到 macOS 的 ~/.zshrc。
  • 使用 Python 的 openai SDK，成功调用第三方平台上的某个兼容模型。
  • 配置了 gpt-chat 命令，可以在终端进行单次提问或连续对话。

二、环境变量是什么

环境变量就是程序可以读取的一组“名称 = 值”配置。本次配置中：

  • OPENAI_API_KEY：证明“你是谁”，用于身份验证。
  • OPENAI_BASE_URL：告诉程序“把请求发送到哪里”。
  • 模型名称：告诉平台“使用哪个模型”，本次为一个示例模型。

直接执行 export 通常只对当前终端有效；写入 ~/.zshrc 后，新终端会自动加载。执行 source ~/.zshrc 可以让当前终端立即重新加载。

环境变量跟随终端及其启动的程序，与当前处于哪个文件夹无关。API Key 属于敏感信息，不要公开或写进共享代码。

三、终端怎样和模型交流

终端本身不是模型。实际过程是：

你输入问题 → 终端启动聊天程序 → 程序通过 API 发出请求 → 远端模型生成回答 → 终端显示回答

本次用法：

# 单次提问
gpt-chat "1+1等于几？"

# 进入连续对话
gpt-chat

连续对话中输入 exit 或按 Ctrl-D 退出。关闭终端不会删除配置；重新打开终端后可直接使用 gpt-chat，但上一次对话的上下文不会保留。

四、终端交流和客户端交流的区别

本质相同：都是把问题发送给远端模型，再展示回答。

  • 终端 gpt-chat：轻量、以文字为主；配置自己管理；关闭后聊天上下文消失。
  • 普通 GPT 客户端：界面更完整，通常提供历史记录、文件上传、图片或语音等功能，具体取决于客户端。
  • Codex 等编程 Agent：除了对话，还会携带代码上下文、连续调用 API，并根据模型回复操作文件或工具。

如果终端和客户端配置了同一个 API 和模型，回答来源可以相同，主要区别是界面与功能。官方客户端通常使用官方服务；这里的 gpt-chat 使用第三方平台，账号、计费和模型来源不是同一套。

五、刚才的 Harness 在哪里

Harness 是模型外部负责组织输入、上下文、工具和执行流程的程序。

刚才的交流使用的是本地 gpt-chat Python 脚本中的极简对话 harness，不是官方客户端的 harness：

  • OpenAI Python SDK 负责请求发送、身份验证和回复接收等通信工作。
  • Python 脚本负责接收输入、保存本次对话、组织消息、循环聊天和显示回复。
  • 示例模型负责在远端生成答案。
你 → 终端 → Python 极简 harness → 第三方 API → 示例模型

它没有文件读写、命令执行和权限管理等能力，因此不同于完整编程 harness。编程 Agent 的 harness 位于本地客户端中，负责代码上下文、工具执行和多轮任务循环；模型本身不负责实际执行这些工具。

六、一句话记住

环境变量是配置，终端和客户端是使用入口，API 是传输通道，Harness 是任务控制程序，模型是在远端生成回答的服务。
